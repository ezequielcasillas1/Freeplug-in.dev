# Project Agent Guide

Use this file as the default onboarding context for every session.

## Why

Next.js 14 (App Router) + React 18 + TypeScript frontend. Architecture is **feature-first**, **type-safe**, and **AI-agent-aware**. Every rule below exists to prevent runaway abstractions, phantom IDs, and spaghetti code generated by AI tools.

## What (Project Map)

- `src/app/` — Next.js App Router: routes, layouts, loading/error boundaries (Server Components **only**)
- `src/features/` — Feature modules: components, hooks, services, types, use-cases
- `src/components/` — Shared UI (CVA-based, no business logic)
- `src/lib/` — Utilities, middleware, API client, error classes
- `src/types/` — Global shared TypeScript types
- `docs/agent-guides/` — Deep reference: architecture, ID rules, conventions

## How (Always Apply)

- **Use existing patterns first.** Do not introduce new abstractions unless necessary.
- **Smallest change that works.** Do not refactor adjacent code unless it reduces real risk.
- **No `any` types.** Ever. Use `unknown` with type guards if shape is unclear.
- **No business logic in components.** All logic belongs in `use-cases/` or `hooks/`.
- **IDs come from the server only.** Never generate, invent, or fabricate IDs in the frontend. The **only** identifier on the client is `userId` from the auth session. Read `docs/agent-guides/id-rules.md` before touching any ID field.
- **Feature modules are isolated.** Import from a feature's `index.ts` barrel only. Never deep-import across features.
- **Server Components by default.** Add `'use client'` only when the component uses browser APIs, event handlers, or React state/hooks.

## Branching

Always use a feature branch. Never push directly to `main`.
